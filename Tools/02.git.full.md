# Git

Git 是一套**分散式版本管理系統**，可以記錄程式碼的修改歷程，並透過 GitHub 進行遠端保存與協作。

- **Git**：管理本機程式碼版本。
- **GitHub**：提供遠端 Git 儲存庫，方便備份、分享與協作。
- **VS Code**：內建 Git 圖形介面，可執行 Commit、Push、Pull 等常見操作。

本課程以 VS Code 圖形介面為主，以下指令提供安裝、操作及日後查閱使用。

## 一、下載與安裝

### 1. Windows

1. 前往 [Git 官方網站](https://git-scm.com/downloads/win) 下載 Windows 版本。
2. 執行安裝程式，建議：
   - 保留 Git Bash。
   - 預設編輯器選擇 Visual Studio Code。
   - 保留 Git Command Line 與第三方工具整合功能。
   - 可勾選「Add a Git Bash Profile to Windows Terminal」。
   - 其他設定原則上維持預設即可。
3. 安裝完成後，重新開啟 VS Code 終端機。

確認 Git 版本：

```bash
git --version
```

### 2. macOS（Intel / Apple Silicon）

可以使用 Apple Command Line Tools 或 Homebrew 安裝 Git。

**方式一：Apple Command Line Tools**

```bash
xcode-select --install
```

**方式二：Homebrew（推薦已使用 Homebrew 者）**

```bash
brew install git
```

日後更新 Homebrew 安裝的 Git：

```bash
brew upgrade git
```

確認版本及執行位置：

```bash
git --version
which git
```

> 兩種安裝方式擇一即可。macOS 可能同時存在不同來源的 Git，實際使用版本由 PATH 搜尋順序決定。

### 3. Ubuntu / Kali Linux（AMD64 / ARM64）

更新套件清單：

```bash
sudo apt update
```

安裝 Git：

```bash
sudo apt install git
```

確認版本：

```bash
git --version
```

Ubuntu 與 Kali Linux 均可透過 APT 安裝，不需要依 ARM64 或 AMD64 分別下載 Git 安裝程式。

## 二、設定個人資訊

Git 會在 Commit 紀錄中保存作者名稱及 Email。

- `user.name`：Commit 作者名稱。
- `user.email`：Commit 作者 Email。
- `--global`：套用至目前使用者的所有 Git 專案。
- 不加 `--global`：一般用於設定目前 Git 儲存庫。

### 1. 設定全域資訊

```bash
git config --global user.name "UserName"
git config --global user.email "Email@example.com"
```

### 2. 確認設定

```bash
git config --global --list
```

查看目前專案實際生效的設定：

```bash
git config --list
```

### 3. 個別專案設定（選用）

先進入已初始化的 Git 專案，再執行：

```bash
git config user.name "UserName"
git config user.email "Email@example.com"
```

> Git 的使用者名稱與 Email 是 Commit 作者資訊，不是 GitHub 登入帳號或密碼。若使用 GitHub，建議使用已驗證的 Email 或 GitHub 提供的隱私 Email。

## 三、複製專案（Clone）

Clone 可以將遠端儲存庫複製到本機，包含 Git 版本紀錄。

基本語法：

```bash
git clone [URL]
```

範例：

```bash
git clone https://github.com/catseng202611/202611.git
```

複製完成後，進入專案資料夾：

```bash
cd 2026AI_05
```

查看目前狀態：

```bash
git status
```

> GitHub 的私人儲存庫需要具有存取權限，並完成適當的身分驗證。

## 四、初始化 Git 儲存庫

當本機已經有專案，但尚未使用 Git 管理版本時，可以執行：

```bash
git init
```

Git 會在專案根目錄建立隱藏的 `.git` 資料夾，用來保存版本紀錄與儲存庫相關設定。

確認狀態：

```bash
git status
```

如需將新儲存庫的主要分支命名為 `main`：

```bash
git branch -M main
```

> `.git` 是 Git 版本管理的核心資料夾，請勿任意修改或刪除。

## 五、Git 例外處理（.gitignore）

`.gitignore` 用來指定不需要交由 Git 追蹤的檔案或資料夾。

常見用途：

- 忽略暫存檔、日誌及備份檔。
- 排除套件相依資料夾。
- 避免將含有密碼或 API Key 的環境設定檔加入版本管理。
- 排除作業系統產生的非必要檔案。

在專案根目錄建立 `.gitignore`，內容範例：

```gitignore
# 忽略備份檔案
*.bak

# 忽略日誌檔案
*.log

# 忽略 Node.js 相依套件
node_modules/

# 忽略 macOS 系統檔案
.DS_Store

# 忽略 Windows 系統檔案
Thumbs.db

# 忽略機密環境設定
.env
.env.*

# 忽略暫存資料夾
temp/
```

### 練習

1. 在專案建立 `test.log`、`index.html.bak` 與 `notes.txt`。
2. 開啟 VS Code 左側「原始檔控制」（Source Control）。
3. 確認未追蹤的檔案是否顯示。
4. 在 `.gitignore` 加入 `*.log` 與 `*.bak`。
5. 再次觀察「原始檔控制」中的變化。

預期結果：

- `test.log`：被忽略。
- `index.html.bak`：被忽略。
- `notes.txt`：仍可被 Git 追蹤。
- `.gitignore`：本身應納入版本管理。

**注意：**

`.gitignore` 主要對尚未被 Git 追蹤的檔案生效。如果檔案已經提交至 Git，新增忽略規則不會自動停止追蹤，也不會刪除過去版本中的內容。

已追蹤的檔案若要停止追蹤，但保留本機檔案，可使用：

```bash
git rm --cached filename
```

再 Commit 並同步到 GitHub。

> 如果密碼或金鑰曾經提交至 Git，僅使用 `.gitignore` 或 `git rm --cached` 不足以移除歷史紀錄中的敏感資料，仍應立即撤銷或更換相關憑證。

## 六、建立版本（Add / Commit）

Git 的基本版本管理流程：

**修改檔案 → Stage → Commit**

### 1. 查看修改狀態

```bash
git status
```

### 2. 暫存修改（Stage）

將目前目錄及其子目錄的變更加入暫存區：

```bash
git add .
```

只加入指定檔案：

```bash
git add README.md
```

### 3. 建立版本（Commit）

```bash
git commit -m "完成第一個版本"
```

### 4. 查看版本歷程

```bash
git log --oneline
```

**記住：**

- `git add`：選擇要納入下一次 Commit 的修改。
- `git commit`：將版本記錄在本機 Git 儲存庫。
- `git push`：將本機提交推送至遠端儲存庫。

> Commit 不等於上傳 GitHub，即使沒有網路，也可以在本機建立 Git 版本紀錄。

## 七、GitHub 遠端同步

### 1. 設定遠端儲存庫

當本機專案尚未連接 GitHub 時，可設定遠端儲存庫：

```bash
git remote add origin [URL]
```

查看目前的遠端設定：

```bash
git remote -v
```

> 使用 `git clone` 複製的專案通常已設定 `origin`，不需要再次執行 `git remote add`。

### 2. 上傳版本（Push）

首次推送 `main` 分支，並設定上游分支：

```bash
git push -u origin main
```

後續如已建立上游追蹤關係，可直接執行：

```bash
git push
```

### 3. 下載並整合遠端更新（Pull）

```bash
git pull
```

`git pull` 會取得遠端更新，並依照設定執行 Merge 或 Rebase。

如果本機與遠端修改產生衝突，可能需要手動處理。

### 4. 僅取得遠端資訊（Fetch）

```bash
git fetch
```

`git fetch` 會更新遠端追蹤分支等資訊，但不會直接將更新合併到目前工作分支。

因此：

- `git fetch`：取得遠端最新資訊。
- `git pull`：取得遠端更新並嘗試整合。
- `git push`：將本機提交推送至遠端。

## 八、分支管理與版本備份（進階）

Git Branch（分支）可以讓開發者在不直接修改主要分支的情況下，進行新功能開發或保存特定版本。

### 1. 查看分支

```bash
git branch
```

列出本機及遠端追蹤分支：

```bash
git branch -a
```

### 2. 建立備份分支

例如建立日期備份：

```bash
git switch -c backup-20261112
```

此指令會建立並切換至新的本機分支。

### 3. 提交目前修改

```bash
git add .
git commit -m "建立備份版本"
```

### 4. 推送備份分支至 GitHub

```bash
git push -u origin backup-20261112
```

### 5. 切換回主要分支

```bash
git switch main
```

**注意：**

- 本機分支不等於遠端備份。
- 若需要 GitHub 保存該分支，必須執行 Push。
- 建立分支本身不會自動建立新的 Commit。
- 若需要完整備份，仍應採用額外的備份機制，不能只依賴 Git 分支。

> 舊版 Git 可使用 `git checkout -b` 建立並切換分支。新版教材建議使用語意更明確的 `git switch -c`。

## 九、強制還原為遠端版本（進階）

當本機專案已經出現不需要保留的修改，希望讓目前的 `main` 分支回到 GitHub 遠端 `main` 的狀態時，可以使用以下方式。

**警告：此操作可能造成資料遺失，執行前請先確認重要修改已備份。**

### 1. 查看本機狀態

```bash
git status
```

確認是否存在未提交修改，必要時先 Commit、建立備份分支或將檔案複製至其他位置。

### 2. 切換至 main

```bash
git switch main
```

若存在可能被覆蓋的本機修改，Git 可能拒絕切換分支，應先處理修改再繼續。

### 3. 取得遠端最新狀態

```bash
git fetch origin
```

此指令只更新遠端追蹤資訊，不會直接改動目前的工作檔案。

### 4. 強制重設本機 main

```bash
git reset --hard origin/main
```

執行後：

- 本機 `main` 會指向 `origin/main` 對應的提交。
- 已追蹤檔案的工作目錄內容會重設為該提交的版本。
- 未提交的已追蹤檔案修改將被捨棄。
- 本機尚未推送、且不在遠端歷史中的提交將不再位於 `main` 的歷史上。
- 一般未追蹤檔案不會被自動刪除，但可能妨礙重設的未追蹤檔案或目錄例外。

### 為什麼不用 git pull？

一般的 `git pull` 會取得並整合遠端修改，不是直接捨棄本機修改。

如果目標是讓本機主要分支完全回到遠端版本，可以使用：

```bash
git fetch origin
git reset --hard origin/main
```

但這是**強制還原操作**，不是一般同步的替代方式。

### 還原後檢查

```bash
git status
git log --oneline -5
```

檢查目前狀態及最近的 Commit 紀錄。

> `git reset --hard` 不會保證清除所有未追蹤檔案，也不是備份工具。如果需要移除未追蹤檔案，應另外評估 `git clean`，但該指令同樣可能造成資料遺失，不建議初學者直接使用。

## 十一、學習重點

1. **Save 不等於 Commit**：儲存檔案不代表建立 Git 版本。
2. **Commit 不等於 Push**：Commit 記錄在本機，Push 才會將提交送到 GitHub。
3. **Git 不等於 GitHub**：沒有網路也能使用 Git 管理版本。
4. **.gitignore 不是刪除工具**：它主要用於忽略尚未追蹤的檔案。
5. **Push 前確認修改內容**：不要將密碼、金鑰或敏感資料提交至遠端。
6. **強制還原前先備份**：避免因 `reset --hard` 造成重要修改遺失。
